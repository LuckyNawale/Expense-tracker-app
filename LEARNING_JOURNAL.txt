============================================================
PROBLEM ENCOUNTERED
============================================================

When I tried:

git push -u origin main

Git rejected the push.

Reason:

The GitHub repository already had its own commit history,
while my local repository had a different history.

Git therefore prevented the remote history from being
overwritten accidentally.

------------------------------------------------------------
INVESTIGATION
------------------------------------------------------------

Command:

git fetch origin

Purpose:

Downloads information about the remote repository without
merging the remote changes into my working files.

------------------------------------------------------------

Command:

git log --oneline --all --decorate

Purpose:

Shows the commit history from the local and remote branches.

I discovered that there were two separate initial commits:

Local:
d7edce9

Remote:
66b91f4

They were unrelated histories.

============================================================
SOLVING THE PROBLEM
============================================================

Command:

git merge origin/main --allow-unrelated-histories

Purpose:

Combines the local history and the existing GitHub history
even though they were created independently.

The merge created:

c93998d

Merge remote-tracking branch 'origin/main'

The existing README.md from GitHub was successfully
combined with my local project.

------------------------------------------------------------

Command:

git log --oneline --decorate --graph --all

Purpose:

Displays the commit history as a visual graph.

Final history:

*   c93998d  Merge remote-tracking branch 'origin/main'
|\
| * 66b91f4  Initial commit
* d7edce9    Initial commit

============================================================
FINAL PUSH
============================================================

Command:

git push -u origin main

Purpose:

Uploads my local commits to the GitHub repository.

The push was successful.

GitHub repository:

https://github.com/LuckyNawale/Expense-tracker-app

------------------------------------------------------------

Final verification:

git status

Result:

nothing to commit, working tree clean

This means the local working directory was clean and
everything had been successfully committed.

============================================================
LESSONS LEARNED
============================================================

1. Git tracks changes to my project.

2. A commit is a checkpoint in project history.

3. A remote connects my local repository with GitHub.

4. "origin" is the conventional name for the GitHub remote.

5. "main" is the branch we are using.

6. git fetch downloads information about remote changes
   without automatically merging them.

7. git log helps inspect project history.

8. Git protects the remote repository when histories differ.

9. I should not blindly use git push --force when a push
   is rejected.

10. Git history should be inspected before deciding how
    to resolve a conflict or rejected push.
